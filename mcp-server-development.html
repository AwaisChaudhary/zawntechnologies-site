MCP server development

We build Model Context Protocol (MCP) servers that let Claude, ChatGPT, Cursor and your own AI agents use your APIs, databases and internal tools through a small, permissioned set of actions, with logging and limits you control.

What an MCP server is, in plain words

MCP is an open standard for connecting AI assistants to outside systems. Instead of writing a separate plugin for every assistant, you build one MCP server that describes what the assistant may do (for example "look up an order" or "create a draft invoice"), and any MCP-capable client can use it. The server is ordinary software: it runs your code, checks permissions and calls your systems. The model only asks; your server decides.

What we build

  • MCP servers for your product's API, so your customers can use your service from Claude, ChatGPT or their IDE
  • Internal MCP servers over your CRM, ERP, helpdesk, database or document store, for your own team's assistants
  • Read-only knowledge servers that let an assistant search docs, tickets or reports without being able to change anything
  • Remote, multi-user MCP servers with sign-in (OAuth), per-user permissions and audit logs
  • Agents that use MCP servers to finish a task over several steps, with approval for anything irreversible (see AI agent development)
  • Reviews and hardening of an MCP server you already have: permissions, input checks, secrets and logging

How it works

  1. User asksIn Claude, ChatGPT, Cursor or your own app
  2. Client picks a toolThe model chooses one of the tools your server lists
  3. Your MCP serverChecks who is asking, validates inputs, applies limits
  4. Your systemsAPI, database or service is called with scoped credentials
  5. Result and logA short result goes back to the model; every call is logged

Anything that changes data, spends money or contacts a customer can require the user to confirm it before the server acts.

The MCP specification and client support change quickly. We build against the current specification version and test with the clients you actually use.

Tech stack

We usually write MCP servers in Python or TypeScript on Node.js with the official MCP SDKs (or FastMCP in Python), behind your existing API. Hosted servers run on your cloud account (AWS, Google Cloud, Azure or a small VPS) or on edge platforms such as Cloudflare Workers, with PostgreSQL or your current database, structured logs and rate limits. We test with the MCP Inspector and with the real clients your users have: Claude desktop and Claude Code, ChatGPT, Cursor, VS Code and agent frameworks such as the OpenAI Agents SDK, Claude Agent SDK and LangGraph.

MCP server or a normal API integration?

  • Choose an MCP server when people will work through an AI assistant, when several different assistants or IDEs need the same access, or when you want your product to be usable from Claude or ChatGPT.
  • Choose a normal integration when one fixed workflow runs on a schedule with no human or model in the loop. A plain script or automation is cheaper and easier to test.
  • Many projects use both: the MCP server is a thin, safe layer on top of an API that also serves your web app.

How we work

  1. Scope (a few hours): which users, which assistants, and the 5 to 15 actions that matter. We write each tool's name, inputs and permission as a short spec you approve.
  2. Build read-only first: search and lookup tools go live before anything can write, so you see how the model uses them.
  3. Add write actions with guards: confirmation steps, limits per user and per day, and dry-run modes where useful.
  4. Test with real clients: MCP Inspector, then Claude, ChatGPT or Cursor with your own example requests, including attempts to misuse the tools.
  5. Deploy and hand over: code in your repository, deployment on your account, logs and a short runbook. Maintenance is optional.

Risks and how we handle them

  • Prompt injection: text in an email, web page or document can try to steer the model. The server never trusts the model's request alone: permissions, limits and confirmations are enforced in code.
  • Too much access: each tool gets the narrowest credential that works; production write access is the last thing we add, not the first.
  • Untrusted third-party servers: installing an unknown MCP server is like installing unknown software. We review servers you plan to use and pin versions.
  • Data exposure: results are trimmed to what the task needs, secrets never go to the model, and logs avoid storing personal data you do not need.
  • Platform rules: if you publish a server or app for ChatGPT, Claude or another directory, you follow that platform's terms and review process; we help prepare it.

Questions clients ask

What does an MCP server developer do?

They design the set of tools an AI assistant may use, write the server that checks permissions and calls your systems, add sign-in and logging, and test it with real clients such as Claude, ChatGPT and Cursor.

How much does it cost to build an MCP server?

At $50 per hour, a read-only server over your docs or one database is usually $1,000 to $2,500, a server exposing a few API actions $1,500 to $4,000, and a remote multi-user server with OAuth sign-in and audit logs $4,000 to $8,000.

Will the same MCP server work with Claude and ChatGPT?

Usually yes, because both support the protocol, but clients differ in which features and sign-in flows they support. We test with each client you name and keep the tools simple so they behave the same way.

Is it safe to let an AI assistant use our systems?

It can be, when the server enforces the rules and not the model: narrow permissions, confirmation for changes, limits, input validation and logs. We start read-only and add write actions only after you have seen how the tools are used.

Local or remote MCP server: which do we need?

A local server (stdio) runs on one person's computer and suits developer tools and personal workflows. A remote server (Streamable HTTP) is hosted once for a team or for your customers and needs proper sign-in, which adds hours but is the right choice for anything shared.

Can you add MCP to our existing SaaS API?

Yes. We usually wrap your existing API rather than change it, choose a small set of task-level tools, reuse your sign-in through OAuth and add rate limits, so your customers can use your product from their AI assistant.
