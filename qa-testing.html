Software QA and testing that catches problems before your users do

We test web apps, mobile apps and APIs with a mix of careful manual testing and automated tests that run before every release.

Quick answer: we test web and mobile software at $50 per hour, including apps another team built. A test plan and a full manual test pass for a typical MVP is usually 20 to 60 hours ($1,000 to $3,000, 1 to 2 weeks); an automated end-to-end suite for the core flows of a web app is usually 40 to 120 hours ($2,000 to $6,000, 2 to 4 weeks) and then runs on every release.

Why teams hire us for this

Bugs found by users cost reviews, refunds and support time. We build test plans around the flows that matter most to your business, then automate the ones that need checking every release.

We can test software we built or software built by another team, and report issues with clear steps to reproduce.

What you get

  • A written test plan that ranks your flows by business risk: sign-up, payments and the core workflow first
  • Bug reports with steps to reproduce, expected and actual results, device and browser, and a screenshot or screen recording
  • Automated tests in your own Git repository, written so your developers can read and extend them
  • Tests wired into your CI pipeline so they run on every pull request or release
  • A short summary after each round: what was tested, what failed, what is fixed and what is still open
  • Retesting of fixed bugs, so you know a fix really works before it ships

How we work

Every engagement starts with a short discovery phase: we learn your users, your data and your constraints, then send a written plan with milestones and a fixed estimate per milestone. You see working software every one to two weeks, and the code lives in your repository from day one.

  1. Learn the product (2 to 4 days): we use the app like a real user, read any specs and agree with you which flows matter most and which devices and browsers to cover.
  2. Test plan: a written list of test cases ordered by risk, shared with you before testing starts.
  3. Test and automate: a manual pass to find today's bugs, then automation for the checks that need repeating on every release.
  4. Report and retest: bugs go into your tracker (Jira, Linear, GitHub Issues or a shared sheet), and we retest each fix and keep the regression suite up to date.

Our rate is $50 per hour. For fixed-scope work we quote per milestone so you know the cost before each stage starts. ZAWN has worked this way since 2014, with a 4.9 average from 356 reviews on Freelancer.com and 99% of projects delivered on budget.

Questions clients ask

Can you test an app another team built?

Yes. We start by learning the product and agreeing with you what matters most, usually sign-up, payments and the core workflow. Bugs are reported in your own tracker so your developers can pick them up directly, and we do not need access to the source code for manual testing.

How much does software testing cost?

At $50 per hour, a test plan and full manual pass for a typical MVP is usually 20 to 60 hours ($1,000 to $3,000). An automated end-to-end suite for the core flows of a web app is usually 40 to 120 hours ($2,000 to $6,000). After that, regression testing before each release is usually 8 to 24 hours.

Manual or automated?

Both. Automation for checks that repeat every release, such as sign-in, checkout and the main workflow. Manual testing for new features, usability and anything that changes too often to be worth automating yet.

Will automated tests break every time the design changes?

Not if they are written well. We target stable test IDs and labels rather than layout details, keep shared steps in one place and avoid fixed waits, so a design change usually means updating one helper instead of dozens of tests.

Do you test on real devices?

Yes. We test on the phones and browsers your users actually use, using our own devices plus a device cloud such as BrowserStack for wider coverage, and emulators for quick checks during development.

Which tools do you use?

Playwright or Cypress for web, Appium for mobile, Postman and Jest for APIs, and k6 for load testing, all wired into your existing CI pipeline such as GitHub Actions.
